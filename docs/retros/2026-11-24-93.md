## Protect

- The code map found that the end-to-end tests check that a guide names each command before they run it ("## Code mapping", "The end-to-end tests follow the real guides"). The three end-to-end test files joined the units before the build, so no test failed by surprise after the guides changed.
- The plan gave the exact sentences of the guides and of their tests (notes of units 1 and 3). When the simplicity reviewer asked to remove four rules, the executor kept them by pointing to their lines in "## Decisions" ("## Review log", "Rejected").
- The stray Orca worker of unit 1 stopped and asked before it fixed forward, and it changed nothing after the answer. The commit of unit 1 holds only the work of the sub-agent ("## Executor notes", first line).

## Improve

- The executor ran its first `cstack helper start implementer --unit 1` without `CSTACK_ORCA_WORKERS=off`, and piped it into `head` ("## Executor notes", first line). Both broke rules of its prompt. It started an Orca worker that edited the files of unit 1 at the same time as the sub-agent. The main conversation then had to answer that worker. This branch removes the helper commands from the guides, so the risk ends once #95 removes the code. [one-off]
- The reviews found two checks that the plan lost when `cstack helper done` left the prompts. Nothing checked that an implementer saved its failing run (commit a2e8ae0), and nothing said what a final message with no kind means (commit 668a65d). When a ticket removes a command from the guides, the plan should list every check that the command made and say what replaces it. [skill]
- The implementer of unit 3 wrote the guide edits before `cstack unit red`, which refused ("## Executor notes", third line). The run used the installed prompt, which keeps these two steps together. Unit 2 of this branch splits them into separate steps. [agent prompt]
- The executor ran `cstack helper wait` while its sub-agent still ran, and the command exited with 1 ("## Executor notes", fourth line). This branch removes that command from the guides. [one-off]
- The executor added its entry under "## Hand-off log" but left the placeholder line of the template above it. [agent prompt]
- The installed `cstack` 0.3.2 has no `cstack audit`, so this retrospective has no audit of the steps, although `main` runs it in the retro phase since #91. [one-off]

## Trap hit

- The end-to-end tests run a command only after they check that the prose of a guide or a prompt names it (`cstack/test/e2e/chain.ts`, lines 185 to 190). So a change to the wording of a guide can break them, and the conventions file does not say so. Here it cost two decisions and changes in three end-to-end test files.
