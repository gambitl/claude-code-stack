## Protect

- The rule that a negative test proves its rule by breaking it worked. After their break checks, the implementers of units 1 and 2 made weak tests stricter, and `cstack unit green` reported the changed test files (plan file, "Executor notes", second item).
- In the `questions` phase, the advisor dropped two of the nine draft conditions, `no-file-map` and `architecture-choice`. No record can decide them, and US-1 AC4 does not ask for them. The list of seven was accepted as recommended (plan file, Blocking question 2).

## Improve

- Unit 2 built `withoutBlock()` on top of `readSteps()`, although `## Decisions` says that it "does not check the steps". Its test had no case with a closed block that holds an invalid step. So nothing failed until a later unit noticed the problem, and commit `d4a45ca` fixed it. A plan line that says what a function must not do needs a test case of its own. [skill]
- Unit 1 listed twelve refusals on its `Test` line. One of them, a second opening line after a valid block, got no test case. The correctness review found it, and commit `83fdfac` fixed it with a test that failed first. An implementer should check that each refusal of its `Test` line has a case before `cstack unit red`. [agent prompt]
- The first fix commit of the `build` phase used `git commit -a`. It mixed code and documentation files under one `Cstack-Unit` trailer, so `cstack plan status` refused it. It had to be split into three commits (plan file, "Executor notes", third item). [agent prompt]
- The short version of the advisor in the `questions` phase came back with `<` and `>` written as `&lt;` and `&gt;`. So it had to be unescaped before it could be shown to the user. [agent prompt]
- The question round placed the CI check of the blocks inside `cstack/test/manifest.test.ts`. The `plan` phase moved it into `cstack/src/guide-steps.ts`, because code inside a test file can never fail first under `cstack unit red`. The `## Decisions` line about `stepProblems()` records this. [skill]

## Trap hit

- A vitest test file that statically imports a module that does not exist yet fails as a whole. No case runs, and the rule "each new test case fails first" does not accept that. `cstack unit red` also refuses a stub of the module before the red run. The plan used a dynamic `import()` inside each case of `cstack/test/guide-steps.test.ts`, which cost one planning decision.
