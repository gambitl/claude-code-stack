## Protect

- The question round compared the rule of the ticket with the rule that `cstack unit collect` uses to keep a child worktree, in `cstack/src/unit/collect.ts`, lines 177 to 187. "Blocking questions", question 3, then widened the check of `cstack helper done` to every uncommitted change except the plan file. With the narrower rule of the ticket, a forgotten file of the unit would still have made the collect keep the worktree.
- The review before the plan replaced the draft answer of "Blocking questions", question 2. Installing nothing without `setupCommand` would have broken every repository, because none has the key yet and cstack 0.3.0 refuses it.
- The four implementers of the first batch ran in their own child worktrees, as the "Hand-off log" says. No collect kept a worktree, because `git worktree list` shows only the ticket worktree after the build.

## Trap hit

- Node's `spawnSync` stops a command after one megabyte of output by default. The `git status` of a child worktree with thousands of untracked files then made `cstack helper done` exit with 5. The correctness review caught it, and commit ec976bc fixed it with a larger `maxBuffer` and a test of 9000 file names. `CLAUDE.md` does not mention this limit.
