## Skills

A skill is a folder with a `SKILL.md` file of instructions that Claude loads when a task matches it.

### My own skills (copied into `skills/`)

- **create-tickets**: Turn an existing project in the team's tracker (Linear, Jira, GitLab, GitHub) and its specification page into a full, dependency-wired set of tickets, decomposed for parallel work (one contract per story, then per-layer tickets, then one integration ticket), grouped by milestone as waves, with bodies in the fixed shape the resolve-issue skill expects. Use it whenever the user gives a project name, URL or id and asks to "create the tickets", "ticketize the project", "decompose the project", "fill the project" or "write the issues". Two gates: the skeleton table first, the full bodies after.
- **design-project**: Co-design a new unit of work with the user through a conversation, then record it as a project in the team's tracker (Linear, Jira, GitLab, GitHub) and as a full specification page in the team's documentation tool (Notion, Confluence, a wiki or a docs folder), cross-linked so the ticketing skill can decompose it with no extra input. Use it whenever the user wants to "start a new project", "frame the next thing to build", "write user stories or a spec for a feature", "design a project before ticketing" or asks to be "grilled" about an idea, even when they do not name the skill. The discovery is a relentless interview: the agent pushes back, asks why until it reaches a real user need, and criticises choices openly.
- **digest-retros**: Read the retrospectives that the resolve-issue skill wrote under docs/retros/ in the repository, group what they report, and propose, one change at a time and only with explicit approval, the edits to the skills, their agent prompts, their templates and the repository's conventions file that those retrospectives justify. Use it when the user asks to "digest the retros", "run the digest", "improve the skill from the retrospectives", or when a resolve-issue run ended with a "Digest due" notice.
- **linear-release-note**: Generate a technical release-notes page in Notion from a closed/shipped Linear PROJECT — enumerating its completed issues (OWL-NN), resolving the GitHub PR that shipped each one via Linear's auto-linked attachments, and diffing against the previous release-notes page to highlight additions, evolutions and removals. Use whenever the user asks to "write release notes", "document the release/project", "publish the changelog", "résumer le projet", "ship the release notes" and the tickets live in a Linear project. Trigger on requests conflating "project/release closure + changelog + diff vs previous version" in a Linear-tracked repo.
- **resolve-issue**: Take one ticket, from any tracker (Linear, Jira, GitLab, GitHub), all the way to a merge-ready pull request, then document the outcome in the ticket, its dependent tickets and the team's documentation tool. Use it whenever the user gives a ticket id or URL and asks to "resolve", "implement", "take", "start" or "work on" it.
